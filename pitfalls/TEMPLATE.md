# 踩坑记录模板

```markdown
# 00x <一句话现象，写具体报错>

**日期**：YYYY-MM-DD
**环境**：芯片型号 / 开发板 / 库 / IDE 版本

## 现象

（贴屏幕截图、串口输出、报错原文）

## 排查过程

1. 先查 X —— 结论：排除/确认
2. 再查 Y —— 结论：...
3. ...

## 根因

（一句话说清机制，不要停在"换个设置就好了"）

## 解决

（改了什么，改在哪一行）

## 学到的

- 一条可迁移的经验

## 对应面试题

- 这条坑可能被问成什么问题
```

## 写作要点

1. **排查过程要写"每一步排除了什么"** —— 这是面试官真正想看的东西
2. **根因必须写到机制层**，不能停在操作层
3. **最后一段把坑转成面试题**，经验才不浪费
4. 当天踩的坑当天写，隔天就忘了细节
