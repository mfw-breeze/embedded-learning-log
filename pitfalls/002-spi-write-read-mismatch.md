# 002 SPI 写 W25Q64 "写正常、读不对"

**日期**：2026-10-30
**环境**：STM32F103C8T6 / W25Q64 模块 / 标准库 / 软件模拟 SPI（PA4~PA7）

## 现象

```
MID:C8  DID:4016      ← ID 能读到，说明物理层和 SPI 时序都是通的
W:A1 B2 C3 D4         ← 我写进去的数组
R:01 02 03 04         ← 读回来是另外四个数
```

第一反应是"写没问题，读坏了"。**这个判断是错的。**

## 排查过程

1. **先质疑"写正常"这个前提**：`W` 那一行打印的是 `main.c` 里的 `ArrayWrite` 常量数组，**不是从 Flash 回读的内容**。SPI 线全拔了它也照样显示 —— 它什么都不能证明。
2. **做位运算对照**：NOR Flash 编程的新值 = 旧值 AND 新值。而
   `0x01&0xA1=0x01`、`0x02&0xB2=0x02`、`0x03&0xC3=0x03`、`0x04&0xD4=0x04`
   —— **四个字节全部原样保留**，说明芯片里本来就存着 01 02 03 04，扇区根本没被擦除。
3. **查擦除为什么没生效**：`W25Q64_ReadID()` 少了 `MySPI_Stop()`，CS 一直停在低电平。

## 根因链

| 步骤 | 芯片看到的东西 | 结果 |
|---|---|---|
| `ReadID` 结束 | CS 仍为低，还在连续输出 JEDEC ID | **事务没结束** |
| `SectorErase` → `WriteEnable` | CS 已是低电平，**没有下降沿**，`0x06` 被当成 ID 数据流的后续时钟 | 命令没被识别，**WEL = 0** |
| `SectorErase` 主体 | `0x20` + 地址，但 WEL = 0 | **擦除被硬件静默忽略** |
| `WaitBusy` | 读 SR1 看到 WIP = 0 | 以为擦完了，正常返回 |
| `PageProgram` → `WriteEnable` | CS 刚被拉高过，`0x06` 是合法命令 | WEL = 1，编程**真的执行了** |
| `ReadData` | 读出未擦除的旧数据 | `01 02 03 04` |

## 解决

1. `W25Q64_ReadID()` 末尾补 `MySPI_Stop();`
2. `MySPI_Init()` 末尾补 `MySPI_W_CS(1);`（GPIO 推挽输出默认低电平，等于开机就把 CS 拉低了）

## 验证

```c
if (memcmp(ArrayWrite, ArrayRead, 4) == 0)
    OLED_ShowString(4, 1, "SAME");
else
    OLED_ShowString(4, 1, "DIFF");
```

反证实验：注释掉 `W25Q64_SectorErase()`，把写入改成 `{0x11,0x22,0x33,0x44}`，读回仍然是 `01 02 03 04`（AND 结果），恢复擦除后才变成 `11 22 33 44`。

## 学到的

- **`0x06` 是一条独立命令**，必须自己拥有一次 CS 低→高，不能接在别的命令后面。
- **擦除失败是不可见的**：`WaitBusy` 只等 WIP 变 0，而命令被忽略时 WIP 本来就是 0 —— "等到了不忙" ≠ "操作成功了"。
- **写入必须回读**。写是一个没有返回值的动作，永远不会报错。
- 除了 CS，**SR1 的 BP0~BP2 写保护位**是第二个"静默失败"来源。
- 顺手修了两个隐患：`WaitBush` 改名 `W25Q64_WaitBusy` 并加 `static`；`PageProgram` 的循环变量 `uint8_t i` 改成 `uint16_t`（超过 255 字节会死循环）。
