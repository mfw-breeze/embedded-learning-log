# 软件 SPI 读写 W25Q64

**日期**：2026-10-30
**参考**：W25Q64FV 数据手册（8MB SPI NOR Flash）
**对应 demo**：[demos/26-softspi-w25q64](../demos/26-softspi-w25q64/)

## 一句话总结

SPI 是**"发一个字节的同时收一个字节"**的全双工总线，没有地址（靠 CS 选片）、没有应答（靠回读确认）；NOR Flash 的**擦除是唯一能把 0 变回 1 的操作**。

## 四线定义

| 线 | 方向 | 本工程引脚 |
|---|---|---|
| CS | 主机 → 从机 | PA4 |
| SCK | 主机 → 从机 | PA5 |
| MISO | 从机 → 主机 | PA6（上拉输入） |
| MOSI | 主机 → 从机 | PA7 |

## 模式：Mode 0

空闲低电平、上升沿采样、MSB 先发。软件实现的关键顺序是 **先在 SCL 低时放数据 → 拉高 → 采样 → 拉低**。

| 模式 | CPOL | CPHA | 采样沿 |
|---|---|---|---|
| **Mode 0** | 0 | 0 | 上升沿（第一个边沿） |
| Mode 1 | 0 | 1 | 下降沿 |
| Mode 2 | 1 | 0 | 下降沿 |
| Mode 3 | 1 | 1 | 上升沿 |

W25Q64 同时支持 Mode 0 和 Mode 3。

## 命令集

| 命令 | 码 | 作用 |
|---|---|---|
| Write Enable | 0x06 | 置 WEL=1，**必须是独立一次 CS 低→高** |
| Read Status 1 | 0x05 | 读 WIP / WEL / BP0-2 |
| JEDEC ID | 0x9F | 厂商 + 容量（0x4017 = 8MB / 0x4016 = 4MB） |
| Sector Erase | 0x20 | 擦 4KB，全变 0xFF，典型 45ms / 最坏 400ms |
| Page Program | 0x02 | 写 ≤256 字节，只能 1→0 |
| Read Data | 0x03 | 连续读，无上限 |

## 擦写状态机（缺一步就会静默失败）

```
1) 0x06  →  WEL = 1
2) 0x20  →  WIP = 1 …… 等回 0（WEL 被硬件自动清 0）
3) 0x06  →  WEL 再置 1   ← 擦除会清掉它，容易漏
4) 0x02  →  WIP = 1 …… 等回 0
5) 0x03  →  回读比对，这一步才叫"写成功"
```

## 物理特性：只能把 1 写成 0

| 操作 | 粒度 | 效果 |
|---|---|---|
| 擦除 | 4KB / 32KB / 64KB / 整片 | 全变 0xFF（唯一能把 0 变 1 的途径） |
| 编程 | 1 ~ 256 字节 | 新值 = 旧值 AND 新值 |

推论：改一个字节也要"读整扇区 → 改内存 → 擦扇区 → 写回"，这就是文件系统和磨损均衡存在的原因。

## 面试可能问什么

- SPI 四种模式怎么定？你怎么确认用的是 Mode 0？
- SPI 没有 ACK，怎么保证数据可靠？（回读 + 状态寄存器 + CRC + 重试）
- 为什么写 Flash 之前必须擦除？为什么不能只擦一个字节？
- CS 的时序要求是什么？漏掉 CS 拉高会怎样？
- 页编程超过 256 字节会发生什么？（回卷到页首）
