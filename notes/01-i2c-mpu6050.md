# 硬件 I2C 读写 MPU6050

**日期**：2026-10-19
**参考**：RM0008 第 26 章（I2C）/ MPU6050 寄存器手册
**对应 demo**：[demos/25-hwi2c-mpu6050](../demos/25-hwi2c-mpu6050/)

## 一句话总结

STM32 的硬件 I2C 用**事件（EV5/EV6/EV8/EV7）**来驱动流程，每一步都是"发起 → 等事件 → 再走下一步"；MPU6050 就是一堆 8 位寄存器，读出 16 位数据后要**按有符号数**解释。

## 接线与配置

| 项目 | 值 |
|---|---|
| 外设 | I2C2 |
| 引脚 | PB10 = SCL，PB11 = SDA（复用开漏 `GPIO_Mode_AF_OD`） |
| 速率 | 50 kHz |
| 从机地址 | 7 位地址 0x68 → 标准库要传 **0xD0**（见下方坑 1） |

## 关键寄存器

| 寄存器 | 地址 | 用途 |
|---|---|---|
| `PWR_MGMT_1` | 0x6B | 写 0x01 唤醒并选 PLL 时钟 |
| `SMPLRT_DIV` | 0x19 | 采样率分频，1kHz/(1+9)=100Hz |
| `CONFIG` | 0x1A | DLPF，0x06 → 5Hz 带宽 |
| `GYRO_CONFIG` | 0x1B | 0x18 → ±2000 °/s（16.4 LSB/(°/s)） |
| `ACCEL_CONFIG` | 0x1C | 0x18 → ±16g（2048 LSB/g）；0x00 → ±2g（16384 LSB/g） |
| `ACCEL_XOUT_H` | 0x3B | 14 字节连续数据起点（加速度 6 + 温度 2 + 陀螺 6） |
| `WHO_AM_I` | 0x75 | 正品应读 0x68；读 0x74 说明是兼容片 |

## 事件映射（标准库）

| 事件 | 宏 | 含义 |
|---|---|---|
| EV5 | `I2C_EVENT_MASTER_MODE_SELECT` | START 已发出 |
| EV6 | `I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED` | 地址 + W 收到 ACK |
| EV6 | `I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED` | 地址 + R 收到 ACK |
| EV8_2 | `I2C_EVENT_MASTER_BYTE_TRANSMITTED` | 字节发送完成 |
| EV7 | `I2C_EVENT_MASTER_BYTE_RECEIVED` | 收到一字节 |

## 代码要点

读一个寄存器 = **两次 START**（第一次写寄存器地址，重复 START 后读数据）：

```c
I2C_GenerateSTART(I2C2, ENABLE);
/* ... 等 EV5 → 发地址+W → 等 EV6 → 发寄存器地址 → 等 EV8_2 */
I2C_GenerateSTART(I2C2, ENABLE);          /* 重复起始，不释放总线 */
/* ... 发地址+R → 等 EV6 */
I2C_AcknowledgeConfig(I2C2, DISABLE);     /* 最后一个字节：先关应答 */
I2C_GenerateSTOP(I2C2, ENABLE);           /* 预约 STOP */
while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_BYTE_RECEIVED) != SUCCESS);
Data = I2C_ReceiveData(I2C2);
I2C_AcknowledgeConfig(I2C2, ENABLE);      /* 恢复 */
```

**改目标**：现在的 `GetData` 是逐字节读 12 次事务，六个轴不是同一时刻采样。
应该从 0x3B 起一次连读 14 字节（代码见踩坑记录 001 的"延伸"）。

## 面试可能问什么

- 为什么 I2C 读寄存器要用重复 START，而不是 STOP + START？
- `I2C_Send7bitAddress()` 为什么传 0xD0 而不是 0x68？
- 读最后一个字节前为什么要关应答？
- I2C 总线死锁（从机拉死 SDA）怎么恢复？
- ±16g 和 ±2g 的量程怎么选？对分辨率有什么影响？
